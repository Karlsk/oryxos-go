# Data Model: LLM Provider Integration

## Process configuration

### `ProviderDefinition`

Represents one connection available to the OryxOS process.

| Field | Go shape | YAML | Rules |
|---|---|---|---|
| Name | `string` | `name` | Required, unique, exactly `deepseek` or `minimax` |
| APIKey | `string` | `api_key` | Required after environment expansion; secret and always redacted |

The existing process configuration gains `Providers []ProviderDefinition`. Provider declarations contain no endpoint, model, temperature, Tool, Skill, Channel, or schedule selection. Strict decoding rejects `base_url`; each explicit Provider factory owns endpoint policy, including deliberately using a native connector's official default.

## Profile configuration

### `ProfileProviderConfig`

| Field | Go shape | YAML | Rules |
|---|---|---|---|
| Name | `string` | `name` | Required and must reference a declared Provider |
| Model | `string` | `model` | Required and non-blank |
| Temperature | `float32` | `temperature` | Optional; default `0.7`; must be a finite numeric value and is passed to the selected connector |

Profile Provider configuration contains no credential or base URL.

### `Profile`

Lesson 16 creates the complete structural container so later lessons extend validation without redefining it.

| Field | Shape | Notes |
|---|---|---|
| Name | `string` | Unique runtime identity; required |
| Description | `string` | Optional display description |
| Identity | struct | `agent_name`, `prompt` |
| Provider | `ProfileProviderConfig` | Validated in lesson 16 |
| Tools | `[]string` | Ordered Tool references; execution is out of scope |
| Skills | `[]string` | Ordered Skill references |
| MCPServers | `[]string` | Ordered MCP connection references |
| NotifyChannels | slice of structs | Structural parsing now; detailed validation belongs to the responsible lesson |
| Schedules | slice of structs | Structural parsing now; detailed validation belongs to the responsible lesson |
| Channels | slice of structs | Structural parsing now |
| Bootstrap | `[]string` | Ordered Bootstrap file references |
| Settings | struct | `max_iterations`, `max_history_turns` |

Unknown YAML fields are rejected. This lesson validates identity and Provider fields needed to construct the model; later lessons add domain validation for Tools, Skills, MCP, notifications, schedules, Bootstrap, and runtime settings.

## Runtime binding

### `ProviderConfig`

Ephemeral merged value passed only to a `ModelFactory`.

| Field | Source |
|---|---|
| Name | Both layers, after equality check |
| APIKey | `ProviderDefinition` |
| Model | `ProfileProviderConfig` |
| Temperature | `ProfileProviderConfig` |

This value is never serialized or logged in full.

### `ProfileModelBinding`

Represented by the registry's model entry rather than a database row.

| Key | Value | Invariant |
|---|---|---|
| `profile.name` | `llm.ChatModel` | One independently constructed OryxOS model adapter per valid Profile |

Factory entries are separately keyed by `provider.name`. Neither map permits silent overwrite.

## Persistence

### `LlmCall`

Maps exactly to the `llm_calls` table.

| Field | Go type | SQL | Rules |
|---|---|---|---|
| ID | `int64` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Generated by SQLite |
| SessionID | `string` | `TEXT NOT NULL` | Required; indexed; links to the logical Session identifier |
| Provider | `string` | `TEXT NOT NULL` | `deepseek` or `minimax` |
| Model | `string` | `TEXT NOT NULL` | Profile-selected model |
| PromptTokens | `int` | `INTEGER NOT NULL DEFAULT 0` | Zero when unavailable |
| CompletionTokens | `int` | `INTEGER NOT NULL DEFAULT 0` | Zero when unavailable |
| TotalTokens | `int` | `INTEGER NOT NULL DEFAULT 0` | Zero when unavailable |
| Success | `bool` | `BOOLEAN NOT NULL` | Outcome of the connector call |
| ErrorMessage | `*string` | `TEXT NULL` | Nil on success; sanitized reason on failure |
| DurationMS | `int64` | `INTEGER NOT NULL` | Non-negative elapsed milliseconds |
| CreatedAt | `time.Time` | `DATETIME NOT NULL` | UTC creation time |

There is no foreign-key declaration in lesson 16 because the `sessions` table is delivered later; `session_id` is nevertheless required and indexed. No credential, prompt body, response body, or Tool arguments are stored in `llm_calls`.

## Validation and state transitions

### Provider declaration

```text
raw YAML
  -> duplicate-key / unknown-field check
  -> allowed environment expansion
  -> supported-name / uniqueness / credential / URL validation
  -> accepted process Provider catalog
```

Any failure is fatal to process configuration loading.

### Profile loading

```text
profile file
  -> strict decode
  -> required-field validation
  -> declared-Provider reference check
  -> duplicate Profile-name check
  -> registry entry + isolated model binding
```

A file can become `registered` or `skipped_with_diagnostic`. A skipped file does not roll back previously registered valid Profiles.

### Model call

```text
started
  -> generate_success | generate_failure
  -> stream_started
       -> stream_completed | stream_receive_failure | stream_early_close
  -> audit_insert_success | audit_insert_failure
  -> result returned only after audit attempt
```

Every logical Generate or Stream invocation causes exactly one audit insert attempt. Stream deltas do not create rows; only its terminal outcome does. A completed stream records usage from the merged terminal response, while failed or prematurely closed streams use zero for unavailable usage. Tool-call intentions remain fields on the returned assistant message and have no execution transition in this feature.
