模块以 `Server`（server.go + component.go）为对外边界，内部组合 `gin.Engine` 与 `http.Server`，通过可注入的 `ListenerFactory` 解耦 TCP 监听器创建，便于测试替换；`Start`/`Close` 使用内部 `startState`（含 `starting/started/closed` 三态与 `sync.Once`）保证并发安全与幂等。

依赖方向严格单向：web 仅依赖 `internal/config`、`internal/observability` 与本模块内的 `api`、`middleware` 子包，不直接访问 Provider connector 或 Store，符合项目“web 不得直接访问 Provider connector 或 Store”的边界约束。

- `api/` 子包定义统一的泛型响应信封 `Result[T]`、分页结构 `PageResult[T]` 及 `Success/Page/Error` 写入函数，内置白名单校验（code/message/detail field/rule），所有响应必须经此通道输出。
- `middleware/` 子包提供 RequestID、RequestBodyLimit、AccessObservation、Recovery 四个 gin.HandlerFunc，按固定顺序挂载到 router。
- `handlers.go` 仅包含 healthHandler 与 infoHandler，通过 observability.Observer 暴露就绪状态与版本信息。
- server.go 注册 `/api/v1/health` 与 `/api/v1/info`，并通过 NoRoute/NoMethod 返回统一错误信封。
