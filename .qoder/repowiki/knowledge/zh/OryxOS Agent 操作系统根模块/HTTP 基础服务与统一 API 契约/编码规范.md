- 所有 HTTP 响应必须通过 api.Success / api.Page / api.Error 写出，禁止直接调用 c.JSON，以保证 code/message/details 的白名单校验与 RequestID 注入。
- 错误码采用 status-code → {code: message} 映射表（errorDescriptors）集中管理，新增错误需同时更新映射与 validErrorDescriptor 校验逻辑。
- 中间件以独立的 gin.HandlerFunc 形式组织在 middleware/ 子包，并按固定顺序（RequestID → BodyLimit → AccessObservation → Recovery）挂载到全局路由。
- 对外部资源（如 net.Listener）通过函数工厂类型（ListenerFactory）注入，便于测试时替换并避免真实端口绑定。
- Server 生命周期使用内部 startState 配合 sync.Mutex、sync.Once 管理 starting/started/closed 三态转换，Start/Close 均幂等且只允许单次成功启动。
- 分页参数解析统一通过 parsePaginationValue 进行无符号十进制校验、范围限制与重复字段检测，并返回标准化的 {field, rule} 详情。
