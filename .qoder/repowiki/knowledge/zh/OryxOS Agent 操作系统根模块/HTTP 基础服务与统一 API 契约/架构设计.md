模块以 `Server`（server.go + component.go）为边界入口，封装 `gin.Engine` 与 `http.Server`，通过可注入的 `ListenerFactory` 解耦监听器创建，使用内部 `startState` 状态机保证 Start/Close 的幂等与并发安全；路由集中在 server.go 中注册 `/api/v1/health` 与 `/api/v1/info`，并通过中间件链（middleware/request_id → body_limit → access → recovery）实现请求级横切关注点。

依赖方向严格单向：web 仅依赖 `internal/config`、`internal/observability` 以及本模块内的 `api`、`middleware` 子包，不直接访问 Provider connector 或 Store 实现，符合项目“web 不得直接访问 Provider connector 或 Store”的边界约束。

- `api/` 子包定义统一的泛型响应信封 `Result[T]`、分页结构 `PageResult[T]` 及 `Success/Page/Error` 写入函数，内置白名单校验（code/message/detail field/rule），所有响应必须经此通道输出。
- `middleware/` 子包提供 RequestID、RequestBodyLimit、AccessObservation、Recovery 四个 gin.HandlerFunc，按固定顺序挂载到 router。
- handlers.go 仅包含 healthHandler 与 infoHandler，通过 observability.Observer 暴露就绪状态与版本信息。
